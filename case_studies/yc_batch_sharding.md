# Case Study: The YC Batch That Forced Sharding

## Why this matters

The uploaded PG essay describes YC learning that partner advising does not scale as a single shared pool beyond a certain batch size. The solution was to shard the batch into smaller groups with dedicated partners.

## Pattern

- Common startup problems recur.
- But advice still needs company-specific context.
- A pool of advisors cannot know every company well as batch size grows.
- Dedicated groups preserve context and improve advising quality.

## Mock-office-hours implication

For us, the equivalent of a dedicated partner is a persistent written memory:

- Company snapshot
- Decision log
- Metrics history
- User learning log
- Previous advice and commitments

## Questions

- What context would a real YC partner remember about us?
- Where is that recorded?
- Did today's advice use our actual history or generic startup advice?

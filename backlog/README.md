# Tech Backlog

`tech.md` is the holding pen for engineering and architecture ideas that are
real but not essential right now — the place to write something down so it
stops occupying founder headspace without becoming this week's work. Like
`sessions/` and `metrics/`, the convention ships and the contents don't:
everything here except this README is gitignored.

## The rules

- **Capture is frictionless.** The founder drops an idea in any conversation;
  the partner appends it here with a date. No template, no ceremony — losing
  the idea is the only failure mode.
- **The partner prioritizes, the founder decides.** Every item gets a tier:
  - **NOW** — moves growth or runway this month, or blocks something that does.
  - **NEXT** — matters soon; promote when a NOW slot frees up or evidence
    changes.
  - **LATER** — real, but neither growth nor survival depends on it. Most
    ideas live here, and that's the point.
- **The test is always the same:** does this make the growth number move or
  the runway longer? "Would be good engineering" is not a tier.
- **Backlog items are not commitments.** Office-hours commitments come from
  the session, not from this file. An item only becomes a commitment when it
  is scheduled into a session with a metric attached.
- **Re-triage on touch.** Whenever a new idea lands, the partner re-reads the
  list and flags anything whose tier no longer matches reality (e.g. runway
  shrank → cost items promote themselves).

## Format (`tech.md`)

```markdown
## NOW
- [2026-06-10] Costs audit — burn dominates default-alive math at current MRR

## NEXT
- ...

## LATER
- [2026-06-10] Redesign homepage — only if landing conversion is the measured bottleneck
```

# YC-Style Office Hours for Protocol / Crypto / Community Startups

## Why this needs adaptation

Protocol startups can easily confuse community energy, token speculation, or narrative resonance with product-market fit. A YC-style loop should force the same discipline as any other startup: real users, real repeated behavior, real value, and compounding growth.

## Replace vanity metrics

| Tempting metric | Better YC-style metric |
|---|---|
| Discord members | Retained active contributors/users |
| Token price | Utility-driven transaction volume or protocol revenue |
| Twitter impressions | Qualified users activated |
| Waitlist | Users who complete the core action |
| Grants announced | Builders/users shipped and retained |
| Community excitement | Repeated valuable work coordinated through the product/protocol |
| Number of partners | Active integrations producing usage |

## Core protocol questions

- Who is the user before the token exists?
- What job are they trying to do?
- What do they do today without the protocol?
- What is 10x better because this is decentralized/community-owned?
- What behavior repeats weekly?
- What scarce resource is being coordinated?
- What would users do if the token price went down 80%?
- What part of the system can be concierge/manual at first?

## Do things that don't scale for protocols

- Personally onboard the first communities.
- Manually help them run the first campaign/fundraise/build cycle.
- Write playbooks for them.
- Manually match contributors, funders, and operators.
- Run a white-glove pilot for one community.
- Track every operational step before encoding it into software/protocol mechanics.

## Community PMF signals

Strong:

- Community returns to use the tool/protocol for real coordination.
- Members contribute work/funds without speculative pressure.
- Other communities ask to copy the workflow.
- The protocol solves a coordination problem that centralized tools do not.
- Usage persists when incentives are reduced.

Weak:

- Users show up only for rewards.
- Governance participation is shallow.
- No one uses it without founder prompting.
- The token is more interesting than the product.
- Partnerships do not create transactions, contributions, or revenue.

## Office-hours rule

Every protocol discussion should eventually become a user/workflow discussion. If it stays at the level of ideology, mechanism design, or community vibes, we are probably avoiding the hard product question.

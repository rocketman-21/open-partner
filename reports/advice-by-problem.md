# YC/PG Advice By Founder Problem

Last updated: 2026-05-12

Use this as a lookup table during office hours.

## "We Need More Users"

Likely root causes:

- Not enough manual recruiting.
- Product not compelling enough.
- Segment too broad.
- Launch mistaken for acquisition.

Use:

- PG: `sources/paul_graham_essays/markdown/079-ds.md`
- PG: `sources/paul_graham_essays/markdown/083-growth.md`
- Startup School: "How to Get Your First Customers"

Office-hours move:

- Name 20 reachable users.
- Contact them manually.
- Personally onboard the first 10.
- Measure activation and follow-up behavior.

## "Users Like It But Don't Come Back"

Likely root causes:

- Compliments mistaken for demand.
- No recurring need.
- First value moment weak.
- Wrong segment.

Use:

- User-learning log: `templates/user-learning-log.md`
- Metrics snapshot: `templates/weekly-metrics.md`

Office-hours move:

- Watch 5 users use it.
- Ask what they do instead when they do not return.
- Segment retained vs churned users.

## "We Need More Features"

Likely root causes:

- Avoiding launch.
- Avoiding sales.
- Not sure which user matters.
- Building for low-signal requests.

Use:

- PG: `sources/paul_graham_essays/markdown/079-ds.md`
- Startup School: "How to Build a Minimum Viable Product"

Office-hours move:

- Pick one feature only if tied to a named user and a measurable behavior.
- Ship the smallest usable version.
- Keep manual work behind the scenes where possible.

## "We Need To Raise"

Likely root causes:

- Real growth opportunity needs capital.
- Or company is default dead and hoping investors save it.
- Or fundraising is a prestige/avoidance loop.

Use:

- PG: `sources/paul_graham_essays/markdown/076-fr.md`
- PG: `sources/paul_graham_essays/markdown/063-aord.md`
- YC SAFE docs: https://www.ycombinator.com/documents
- Fundraising template: `templates/fundraising-readiness.md`

Office-hours move:

- Decide fundraising mode or not.
- Calculate default alive/dead.
- Build investor pipeline.
- Track investor actions, not sentiment.

## "Investors Are Interested But Not Committing"

Likely root causes:

- Interest is not commitment.
- Proof is insufficient.
- Process is too serial.
- Founder is interpreting politeness as demand.

Use:

- PG: `sources/paul_graham_essays/markdown/076-fr.md`
- YC Handshake Protocol: https://www.ycombinator.com/handshake

Office-hours move:

- Ask each investor what happens next.
- Push for explicit terms/commitment.
- Run parallel process.
- Improve proof or stop fundraising.

## "We Need To Hire"

Likely root causes:

- Real capacity constraint.
- Or avoidance of founder-led sales/support/product work.
- Or post-raise overhiring pressure.

Use:

- PG: `sources/paul_graham_essays/markdown/063-aord.md`
- Weekly metrics: `templates/weekly-metrics.md`

Office-hours move:

- Define the repeatable job.
- Prove founders have done it manually.
- Calculate burn/runway impact.
- Delay vague hires.

## "We Need A Big Launch"

Likely root causes:

- Hoping attention substitutes for demand.
- Avoiding one-by-one recruiting.
- Product not easy to try yet.

Use:

- PG: `sources/paul_graham_essays/markdown/079-ds.md`
- HN Launch prep: `templates/launch-hn-prep.md`
- YC launch material: https://www.ycombinator.com/launches

Office-hours move:

- Make product tryable.
- Write clear launch copy.
- Recruit manually before and after launch.
- Follow up with every serious user.

## "We Have Too Many Things To Do"

Likely root causes:

- No ranked bottleneck.
- Founder anxiety.
- Fake work competing with real work.

Use:

- PG: `sources/paul_graham_essays/markdown/019-users.md`
- Triage: `templates/problem-priority-triage.md`

Office-hours move:

- Rank by existential risk and learning speed.
- Choose one priority.
- Explicitly pause everything else.

## "The Market Is Huge"

Likely root causes:

- Market size used as substitute for user specificity.
- No initial wedge.

Use:

- PG: `sources/paul_graham_essays/markdown/081-startupideas.md`
- PG: `sources/paul_graham_essays/markdown/083-growth.md`

Office-hours move:

- Name the smallest group with urgent need.
- Explain why this can expand later.
- Find the first users by name.

## "A Big Company Wants To Partner"

Likely root causes:

- Distraction.
- Slow enterprise process.
- Search for validation.

Use:

- PG: `sources/paul_graham_essays/markdown/069-corpdev.md`
- PG: `sources/paul_graham_essays/markdown/079-ds.md`

Office-hours move:

- Ask whether this produces users/revenue this month.
- Avoid custom work without clear payment/learning.
- Prioritize direct customer pull.

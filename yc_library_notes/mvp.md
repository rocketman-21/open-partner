# YC Startup Library Notes: MVP

## Core idea

An MVP is not the smallest product you can imagine. It is the smallest thing that lets a real user experience real value and lets founders learn what to build next.

## MVP traps

- Building infrastructure before user value.
- Building a broad version for a vague market.
- Treating MVP as low quality instead of narrow quality.
- Refusing to launch because the product is embarrassing.
- Automating workflows before manually understanding them.

## Good MVP questions

- What is the user's job?
- What is the smallest version that helps with that job?
- Can a founder manually complete part of the job?
- What must be true for the user to come back?
- What will this MVP teach us within one week?

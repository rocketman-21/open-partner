# Session Protocol

Use this as the concise live checklist. For the full version, use `playbooks/pg_yc_office_hours_workflow.md`.

## Pre-session requirements

Founder fills out:

- `templates/oh_prep.md`
- `templates/weekly-metrics.md`
- previous `templates/session-summary.md`, if any

The assistant/partner should review:

- `sources/pg_yc_office_hours_source_matrix.md`
- `office_hours_corpus_map.md`
- `playbooks/source_backed_retrieval_protocol.md`

## Step 1: prior commitment

Ask:

- What did we commit to last time?
- Did it happen?
- What changed because of it?
- What did it teach us?

If the commitment was not done, diagnose why before moving on. Repeated non-completion is a founder/focus problem, not a scheduling accident.

## Step 2: facts and numbers

Ask for numbers first:

- Revenue / paid commitments
- Active users or active accounts
- Activation rate / first value moment
- Retention / repeat core action
- Weekly growth rate
- Burn / runway / default alive-dead
- User conversations since last session
- Product shipped since last session

Rule: separate facts from interpretation.

## Step 3: source routing

Before advice, pick sources.

Minimum default set:

- `pg_essays/what_ive_learned_from_users.md`
- `pg_essays/startup_equals_growth.md`
- `pg_essays/do_things_that_dont_scale.md`

Then add sources from `sources/pg_yc_office_hours_source_matrix.md` based on the specific bottleneck.

State:

```md
Source anchors for this session:
- [source] because [reason]
```

## Step 4: diagnose the problem class

Classify the main issue:

- Survival / default dead
- User/ICP clarity
- Product value
- Activation/onboarding
- Retention/repeated use
- Growth/distribution
- Sales/pricing
- Fundraising/runway
- Cofounder/team
- Focus/morale
- Crypto/community vanity metrics

## Step 5: challenge the founder diagnosis

Ask:

- Is this a root cause or symptom?
- What evidence supports it?
- What would make us change our mind?
- What problem kills us or blocks growth if ignored?
- What uncomfortable action are we avoiding?

## Step 6: choose one priority

Priority should be:

- connected to the bottleneck
- founder-owned
- measurable
- doable in 2-7 days
- likely to produce new evidence

If there is a P0 survival issue, do not discuss P2/P3 topics.

## Step 7: define the action

Use:

```md
Hypothesis:
Source anchors:
Target users/accounts:
Action:
Owner:
Deadline:
Metric:
Expected result:
Failure signal:
Fallback if it fails:
What we are explicitly not doing:
```

Good metrics are behavioral:

- Revenue collected
- Paid commitments
- Activated accounts
- Retained users/accounts
- Repeat core actions
- Qualified sales calls completed
- Time-to-value
- Churned users interviewed

## Step 8: close with commitment

Write:

- By [date], we will [action].
- We expect [result].
- We will measure [metric].
- If [failure signal], we will [fallback].
- We are not working on [stop-list].
- Next session starts by reviewing [specific question].
